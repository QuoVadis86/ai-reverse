# Douyin a_bogus JSVMP Reverse Engineering Notes

## Overview

`a_bogus` is a request signature parameter used by Douyin (TikTok) Web API.
It's generated by the **bdms** (ByteDance anti-bot SDK) which uses JSVMP
(JavaScript Virtual Machine Protection) to obfuscate its code.

## Architecture

```
app request → axios → XHR.open()
  → bdms SDK intercepts (JSVMP VM runs bytecode)
  → appends &a_bogus=xxx to URL
  → sdk-glue adds x-secsdk-csrf-token header
  → secsdk (strategy engine) executes
  → XHR.send()
```

## JSVMP Bytecode Storage

The VM bytecodes are stored in bdms.js as **base64 → XOR → LZ77 compressed** binary:

```
bdms.js 中的 J("base64string") 调用
  → atob → raw binary (29KB)
  → bytes 0-3: PK\x02\x00 (magic)
  → bytes 4-7: checksum (sum of 4 bytes)
  → bytes 8+: XOR'd with key = checksum % 256
  → XOR formula: byte ^ (key + (key%10) * index) % 256
  → XOR'd data → Custom LZ77 decompress → decompiled binary
  → Parse binary with W() varint reader + K() string reader
  → Populates global arrays Z[] (string table) + z[] (VM functions)
```

### Decompiled Binary Format

```
W(varint) = number of string table entries (Z)
  for each: K() → string → push to Z
W(varint) = number of VM functions (z)
  for each:
    W() = bytecode length
    bytecodes[] = W() x length  (opcode values)
    W() = flags (isConstructor boolean)
    W() = number of source quads
    quad[] = [W,W,W,W] x quad count
    W() = number of string refs
    strRefs[] = Z[W()] x ref count
```

### String Reader K(t)

```javascript
function K(t) {
    for (var r = -1, e = new Array; ; ) {
        var n = t.d[t.i++]; // read byte
        if (n >= 128 && n < 192) // continuation byte
            r = (r << 6) + (63 & n);
        else if (r >= 0 && e.push(r), n < 128)
            r = n;
        else if (n < 224)  r = 31 & n;
        else if (n < 240)  r = 15 & n;
        else if (n < 248) { r = 7 & n; }
        // push when character is complete
    }
    return String.fromCodePoint.apply(null, e);
}
```

### Varint Reader W(t)

```javascript
function W(t) {
    for (var r = 0, e = 0; ; ) {
        var n = t.d[t.i++];
        r |= (127 & n) << e;
        e += 7;
        if (!(128 & n)) // last byte
            return e < 32 && 64 & n ? r | -1 << e : r;
    }
}
```
Signed LEB128 encoding.

### D(t, r) - Function Wrapper Creator

```javascript
function D(t, r) {
    var e = z[t]; // get bytecode config from global z[]
    Y.has(t) && V.delete(Y.get(t));

Called once at init with the base64 string. Decompresses and populates
Z[], z[], V (Map).

```

## Critical: C(k) Decompressor

`C(t, r)` calls `k(t, {i:2}, r.out, r.dictionary)`.

The `k` function is a **custom LZ77 decompressor** defined inside the bdms
IIFE closure. It reads bit-packed data with Huffman-coded match references.

**Key challenge**: `k` depends on closure variables (`t = Uint8Array`, lookup
tables `v`, `i`, `u`, `f`, `s`, and functions `P` bit reader, Huffman builders).
These are defined in the webpack module scope and not easily extracted.

**Location**: bdms.js around position 89768, defined as:
```javascript
k = function(r, e, n, o) { var c = r.length, a = o ? o.length : 0; ... }
```

## Finding the a_bogus Function

When the page loads, `bdms.init` is called. During XHR.open interception,
the JSVMP executes function(s) from `z[]` that:

1. Read the URL from the XHR object
2. Collect device/browser fingerprint (from FYModule, navigator, etc.)
3. Compute the a_bogus signature string
4. Append `&a_bogus=<signature>` to the URL
5. Set the modified URL on the XHR object

The original URL (before bdms) is stored in `xhr._tnc_original_url`.

## How to Continue (for next AI)

The goal is to **extract the bytecodes and create a .vmasm file** for
rc-devtools analysis, OR implement the a_bogus generation in Python.

### Approach A: Extract VM Functions from Memory

1. Open douyin.com in rc-devtools browser
2. Set breakpoint inside the `X` function (line 2, ~col 131082 of bdms.js)
3. Reload - execution will pause when bdms runs
4. Evaluate: `z` (the VM functions array) in the [script] scope
5. Dump each z[i][0] (bytecodes) and z[i][3] (string table)
6. Convert to vmasm format
7. Load vmasm with `rc-devtools_load_vmasm`
8. Set breakpoints at key addresses to trace a_bogus generation

### Approach B: Node.js Decompression

1. Extract `k` decompressor source from bdms.js
2. Extract lookup tables `s`, `v`, `i`, `u`, `f` from the closure
3. Implement in Node.js: XOR → LZ77 decompress → parse binary → output vmasm

## Timing Issue

The bdms.js script loads and executes synchronously during page load.
By the time rc-devtools breakpoints are registered, bdms has already
finished executing. The `z[]` array is populated before any page JS
runs.

### Solution: Playwright addInitScript

Use Playwright's `addInitScript()` to inject capture code BEFORE any
scripts run on the page:

```javascript
// This runs before any page script
await page.addInitScript(() => {
    // Hook into webpack module system or the J() function
    // Example: patch Array.push to capture z[] entries
    const origPush = Array.prototype.push;
    Array.prototype.push = function(...args) {
        // Check if this is the z array being populated
        // (z starts empty and gets ~43 entries of bytecode configs)
        if (this.length === 0 && args.length > 0 && Array.isArray(args[0])) {
            window.__bdms_z = window.__bdms_z || [];
            window.__bdms_z.push(args[0]);
        }
        return origPush.apply(this, args);
    };
});
```

This hooks ALL Array.push calls, so it needs careful filtering.

### Alternative: Hook Uint8Array

The `J()` function creates `Uint8Array` instances during decompression.
Hook `Uint8Array.from` or `Uint8Array` constructor to save the
decompressed data:

```javascript
const origFrom = Uint8Array.from;
Uint8Array.from = function(source, mapFn, thisArg) {
    const result = origFrom.call(this, source, mapFn, thisArg);
    if (source.length > 10000) { // likely the bytecode data
        window.__bdms_binary = result;
    }
    return result;
};
```
